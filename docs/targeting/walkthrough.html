概览

定向召回 (Targeting Recall) 解决「item 携带规则、用户携带属性」的反向匹配问题： 给定一批用户属性，从百万级候选 item 中筛出所有 targeting 规则被满足的 item。 本系统将所有规则编译为 Two-Level Gather + Reduce 的纯 tensor 操作， 经 AOTInductor 导出为 .pt2，支持亚毫秒级在线推理。

本示例用 5 条规则 + 1 个用户 完整走一遍从离线构建到在线匹配的全过程， 重点演示 != 取反的 XOR negated 处理逻辑。

Schema

schema = Schema( discrete_fields=["city", "gender"], numeric_fields=["age"], text_fields=[], )

用户属性

user = {"city": "北京", "gender": "男", "age": 30}

此用户应匹配 item 0, 2, 3, 4（北京男性、年龄 30 满足 > 18 和 >= 25、且不在广州）。

离线构建 (TargetingBuilder.build)

1

解析规则 → DNF → 谓词注册

逐条规则解析为 AST → DNF（析取范式 = OR of ANDs），同时收集所有原子谓词去重分配 pred_id。 != 在解析阶段统一为 == + negated=True，注册表中只存正向谓词。

逐条 DNF 转换

# item 0: city=="北京" AND gender=="男" DNF = [[city=="北京", gender=="男"]] # 1 conj, 2 preds # item 1: city=="上海" DNF = [[city=="上海"]] # 1 conj, 1 pred # item 2: age > 18 DNF = [[age>18]] # 1 conj, 1 pred # item 3: (city=="北京" OR city=="上海") AND age>=25 DNF = [[city=="北京", age>=25], [city=="上海", age>=25]] # 2 conj × 2 preds (OR 展开) # item 4: city!="广州" AND age>18 ← 关键: 含 != DNF = [[city=="广州"(negated!), age>18]] # 注册时标准化: != → == + negated=True

★ 由 item 4 的 != 标准化而来
关键观察 — != 不是新谓词类型

注册表里只有 == 一种正向谓词。city != "广州" 没有产生独立的 != 谓词， 而是注册为 city == "广州" (pred 5)，把取反信息放到 conjunction 的 negated 位上 — 这样 forward() 中只需一次 XOR 就能统一处理 == 和 !=。

2

构建 Conjunction 张量 [C, K]

把所有 item 的 conjunction 扁平化收集为 C=6 条，每条包含一组 (pred_id, negated)。 填入三个固定宽度 [C, K] 张量（K=8）。

扁平化 (item_conjs → all_conj_preds)

all_conj_preds = [] # 全局 conjunction 数组 item_conj_offsets = [] # 每个 item 的 conj 全局编号 for conjs in item_conjs: offsets = [] for conj in conjs: offsets.append(len(all_conj_preds)) all_conj_preds.append(conj) item_conj_offsets.append(offsets) # 结果: # item_conj_offsets = [[0], [1], [2], [3, 4], [5]] ← item 3 拥有 2 个 conj # C = 6

填充三个 [C=6, K=8] 张量

绿色 = True/有效；条纹 = padding；黄色边框 = negated=True。

为什么需要固定宽度 K=8？

torch.export 要求所有张量形状在编译时确定。如果 conj 的谓词数不固定，无法导出为 .pt2。 K=8 = 单条 conj 最多 8 个谓词；padding 槽位的 ids=0 是无意义默认值 — forward() 会通过 | ~valid 把它们设为 True，让它们不影响 AND 规约。

3

构建 Item-Conjunction 张量 [N, J]

用 Phase 2 记录的 item_conj_offsets 把 item → conjunction 的引用关系写入两个固定宽度 [N, J] 张量（J=16）。

item 3 是唯一拥有多个 conjunction 的 item（OR 关系）；其余 item 各引用 1 条 conj。 item 4 引用 conj 5 — 即包含 negated=True 槽位的那一条。J=16 的逻辑同 K=8，固定宽度 + validity mask 满足 torch.export 静态形状约束。

★

在线推理

A

encode_user — 用户属性 → pred_satisfied

对照谓词注册表逐个评估，得到 pred_satisfied [P=6] bool。可点击下方修改用户属性，实时观察影响。

默认: city="北京", gender="男", age=30

评估每条谓词

注意 — pred 5 评估的是 city == "广州"

encode_user 完全不知道有 "!=" 的概念，它只评估正向谓词。 默认用户 city="北京" → pred 5 = False。 取反逻辑要等 forward() 的 XOR 一步处理。

B

forward() — 6 行 tensor 操作

整个推理 = 2 次 gather + 2 次 reduce，共 6 个子步。点击下方按钮逐步观察每一步的张量变化。

关键不对称： conj.padding 用 | ~valid 设为 True（AND 单位元，不影响 all 结果）； item.padding 用 & valid 设为 False（OR 零元，不影响 any 结果）。

★

最终结果

默认用户 (北京/男/30) → 匹配 item 0, 2, 3, 4，过滤 item 1。修改上方用户属性可实时观察结果变化。

item 4 的关键路径（!= 取反）

city != "广州" ↓ 注册阶段: city == "广州" (pred 5) + negated=True ↓ encode_user: pred_satisfied[5] = False # 用户 city="北京", 不在广州 ↓ forward gather: sat[conj 5, k=0] = pred_satisfied[5] = False ↓ forward XOR negated: False XOR True = True ← 取反翻转! "用户不在广州" 成立 ↓ AND age>18(True): conj 5 = True → item 4 ✓

Tensor 速查

离线构建的 Tensor (registered buffer)

conj_pred_ids[C, K] int64
每条 conjunction 引用的谓词 ID。padding 槽位填 0（无意义）。
sat = pred_satisfied[:, conj_pred_ids]
本例: [6, 8]，仅前 2 列有真实值
conj_pred_negated[C, K] bool
该谓词是否取反。!= 标准化后这里为 True，其余为 False。
sat = sat ^ conj_pred_negated
本例: 仅 conj 5 的 k=0 位为 True
conj_pred_valid[C, K] bool
槽位是否有效。padding 位为 False；用 | ~valid 把 padding 设为 True（AND 单位元）。
sat = sat | ~conj_pred_valid
本例: 多数 conj 仅 k=0~1 有效
item_conj_ids[N, J] int64
每个 item 引用的 conjunction 全局编号。多 conj 时表示 OR 关系。
item_conj_ok = conj_ok[:, item_conj_ids]
本例: [5, 16]，item 3 引用 [3, 4]
item_conj_valid[N, J] bool
item 的 conj 槽位是否有效。padding 位为 False；用 & valid 把 padding 设为 False（OR 零元）。
item_conj_ok = item_conj_ok & item_conj_valid
本例: 仅前 1~2 列有效
pred_satisfied[B, P] bool · 输入
用户编码结果，唯一动态输入。Python 侧 encode_user 生成；C++ 侧从 tensors.pt 加载。
def forward(self, pred_satisfied, query):
query 参数被忽略（统一接口需要）

推理过程的中间 Tensor

Tensor形状含义来源
sat (gather)[B, C, K] bool每条 conj 引用的 K 个谓词的当前满足情况Step 1a: pred_satisfied[:, conj_pred_ids]
sat (xor)[B, C, K] bool处理 NOT 之后Step 1b: sat ^ conj_pred_negated
sat (or-pad)[B, C, K] boolpadding 位设为 TrueStep 1c: sat | ~conj_pred_valid
conj_ok[B, C] bool每条 conjunction 是否所有谓词都满足Step 1d: sat.all(dim=2)
item_conj_ok[B, N, J] bool每个 item 的各 conj 是否满足（含 padding）Step 2a: conj_ok[:, item_conj_ids]
item_ok[B, N] bool每个 item 是否最终匹配Step 2b: (... & item_conj_valid).any(dim=2)
scores[B, N] float0.0 (匹配) / -inf (未匹配)torch.where(item_ok, 0.0, -inf)

B=batch 大小，本示例 B=1。所有维度都是静态形状，可被 AOTInductor 编译。
