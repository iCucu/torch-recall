项目概览

基于 PyTorch 的召回框架。每种召回方法实现为统一的 RecallOp（nn.Module）， 通过声明式 And / Or 灵活编排，经 AOTInductor 导出为单一 .pt2 模型包， 支持 C++ / Python 在线推理。

核心优势

All-in-One 模型包

不同召回方法（定向、KNN、生成式）编译为单一 .pt2 模型包。 无需分别部署多个召回服务，一次加载即可完成所有召回逻辑。

📦
单模型部署
多种召回方法 + 组合逻辑 + topk 全部封装进一个 .pt2 文件，线上只需加载一个模型。
🔄
统一接口
所有 RecallOp 共享相同的 forward(pred_satisfied, query) → scores 签名，新增召回方法零适配成本。

声明式灵活组合

通过 And（交集 / 分数求和）与 Or（并集 / 分数取 max）声明式编排，任意嵌套。 从简单的单路召回到复杂的多路融合，只需改 spec 声明，无需修改推理代码。

🧩
And / Or 任意嵌套
And = 分数求和，-inf 自然排除不匹配项；Or = 取 max，任一匹配即包含。支持任意深度嵌套。
⚡
声明即运行
修改一行 spec → 重新 build → 新的 .pt2。在线推理代码完全不变：pipeline(pred, query)。

编译与推理

所有操作均为纯 tensor 操作（无 Python 循环在数据维度上、无动态形状）， 兼容 torch.export 和 AOTInductor，可导出为 C++ 可加载的 .pt2 包。

🚀
AOTInductor 编译
torch._export.aot_compile → .pt2。编译期优化算子融合、内存布局，推理零 Python 开销。
🖥️
C++ 推理引擎
内置通用 C++ 推理引擎，torch::inductor::AOTIModelContainerRunnerCpu 直接加载 .pt2，适用于生产环境。
📐
纯 Tensor 操作
无 if/else 分支在数据维度上，无 Python dict/list，无动态 shape。Targeting 用 DNF 矩阵化，Generative 用 CSR + Dense 混合 Trie。
🎯
Batch 推理
所有 RecallOp 原生支持 batch 维度 [B, ...]，多用户请求可并行处理。

召回方法

框架内置三种召回方法，均实现统一的 RecallOp 接口。可单独使用，也可通过 Pipeline 组合。

Targeting
定向召回 · 布尔规则匹配
根据用户属性对 item 定向规则做精确匹配。支持 == != > contains 等运算符，AND / OR / NOT 嵌套。规则编译为 DNF 矩阵，纯 tensor 操作。
返回 0.0（匹配）/ -inf（不匹配）
忽略 query 参数
端到端示例 → 设计文档 →
KNN
近邻召回 · 向量相似度
Brute-force matmul 计算 query 与所有 item embedding 的相似度。支持 cosine、inner product、L2 三种距离度量。适合中小规模候选集。
返回相似度分数 [B, N]
忽略 pred_satisfied 参数
文档编写中
Generative
生成式召回 · Trie 约束 Beam Search
将 item 编码为语义 ID 路径，组织成 Trie 前缀树。自回归 decoder 逐层生成，Dense/CSR 混合查表，内置 targeting 剪枝。能力上限高于静态 embedding。
累积 log-probability 分数
4 Phase: Mask → Propagation → Beam → Resolve
设计文档 → 交互式示例 ★

统一算子接口

方法forward 签名返回值语义特点
Targeting pred_satisfied [B, P] → [B, N] 0.0 / -inf 忽略 query，纯布尔匹配
KNN query [B, D] → [B, N] 相似度分数 忽略 pred_satisfied，matmul
Generative pred_satisfied + query → [B, N] 累积 log-prob 同时使用两个输入，内置 targeting
And sum(children) → [B, N] 分数叠加 -inf 使不匹配项自然排除
Or max(children) → [B, N] 取最大 任一子节点匹配即包含

架构总览

Builder → RecallOp → Encoder 三层分离。Builder 离线构建索引，RecallOp 负责纯 tensor 推理，Encoder 将业务输入编码为 tensor。

示例：Or( And(Targeting, KNNcosine), And(Targeting, Generativebeam=10) ) → topk(K)

Builder → RecallOp → Encoder

组件职责示例
Builder 离线构建索引，生成 RecallOp + meta JSON TargetingBuilder, KNNBuilder, GenerativeBuilder
RecallOp 纯 tensor 推理，forward() 可编译导出 TargetingRecall, KNNRecall, GenerativeRecall
Encoder 将业务输入编码为 forward() 所需 tensor encode_user, encode_query, encode_pipeline_inputs
Decoder (仅 Generative) 外部传入的 nn.Module，根据用户表征 + 已选前缀输出 logits MockDecoder (测试用)

最小代码

from torch_recall.schema import Schema, Item from torch_recall.scheduler import ( And, Or, Targeting, KNN, Generative, PipelineBuilder, export_recall_model, encode_pipeline_inputs, ) # 定义 Schema + Item schema = Schema(discrete_fields=["city"], numeric_fields=["age"]) items = [ Item(id="item-0", targeting_rule='city == "北京"', embedding=[0.9, 0.1, 0.0]), Item(id="item-1", targeting_rule='city == "上海"', embedding=[0.1, 0.9, 0.0]), Item(id="item-2", targeting_rule='age > 18', embedding=[0.5, 0.5, 0.5]), ] # 声明 + 构建 + 导出 spec = And(Targeting(schema), KNN(metric="cosine")) pipeline, meta = PipelineBuilder(spec, k=2).build(items) export_recall_model(pipeline, "pipeline.pt2") # 在线查询 pred, query = encode_pipeline_inputs( user_attrs={"city": "北京", "age": 25}, query_vectors=[[0.8, 0.2, 0.0]], meta=meta, ) top_scores, top_indices = pipeline(pred, query)
